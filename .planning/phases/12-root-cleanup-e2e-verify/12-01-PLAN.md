# Phase 12 — 根目录清理与端到端验证 (Plan 01)

## Goal

清理仓库根目录 3 个临时/空文件残留，把 `.planning/**` 和 `.codegraph/**` 加入 `.vscodeignore`
将 `.vsix` 体积从 ~5.78MB 压到 < 2MB；运行 typecheck / lint / test:unit 全量验证 v1.3 无回归；
最终通过 EDH (F5) 手工确认状态栏按钮出现。

## must_haves (goal-backward verification)

For Phase 12 to be considered successful, the following must be TRUE:

1. `test -f temp_writer.js; echo $?` == 1（已删除），`temp_writer.mjs`、`ANALYSIS_detection_build.md` 同理。
2. `grep -E 'temp_writer\.(js|mjs)' .vscodeignore` 匹配数 == 0（文件已删，条目已清）。
3. `grep -E '^\.planning/\*\*$' .vscodeignore` 匹配 >= 1。
4. `grep -E '^\.codegraph/\*\*$' .vscodeignore` 匹配 >= 1。
5. `.vsix` 文件大小 < 2MB（2000000 bytes）：`stat -c%s vscode-ue-helper-*.vsix` 输出整数 < 2000000。
6. `npm run package` 输出不包含 "WARNING" 字样（`grep -i WARNING` 匹配数 == 0）。
7. `npm run typecheck` 退出码 0。
8. `npm run lint` 退出码 0。
9. `npm run test:unit` 退出码 0 且测试数量与 v1.3 前一致（无新增失败、无新增跳过）。
10. EDH 测试人工通过：F5 启动扩展宿主，状态栏应出现 8 个 UE Helper 按钮。

## Notes for executor

- T1 使用 `git rm` 而非裸 `rm`，让删除动作进入暂存区，配合后续端到端提交。
- T1 不要主动清理 `.vscli`（未提交状态）；T3a 需要先 `rm *.vsix` 删除旧版本，否则会被老版本的 5.78MB 产物干扰。
- T2 的三条命令**顺序执行、串行等待**，不要并行（typecheck 先于 lint 先于 test 是常见依赖关系，且并行会抢 CPU 影响测试稳定性）。
- T2 中的 `npm run test:unit` 不要加 `--run` 参数，让 vitest 主进程接管；CI 模式即可。
- T3a 运行 `npm run package` 时 prepackage hook 会自动先 build + clean，所以**不要**手动提前 build，避免双次构建。
- T3c 明确标注 `manual_step` 标签 — subagent 执行完 T3a / T3b 后必须把人工指令交给父 agent，**不要**模拟“按 F5”。
- 整个 phase 构建产物唯一 ".vsix"，文档产物仅有 updated .vscodeignore；无新增源码文件。
