<objective>
Wire the already-parsed --localization-* CLI arguments from parseArgs() into the LspBridge
constructor so the localization engine actually receives its configuration.

Purpose: Fix the root bug where cli.ts:runProxy() parses localizationEnabled/mode/targets
via parseArgs() but never passes a LocalizationOptions object to new LspBridge(...). The
bridge and localization engine are fully implemented and correct -- they simply lack the
input connection. Per D-01 and D-02, the fix is scoped to cli.ts only (~10 lines).

Output: cli.ts imports createDefaultLocalizationTable, constructs LocalizationOptions from
parsed CliOptions, and passes it to LspBridge. When --localization-enabled is absent,
undefined is passed (backward compatible per LOC-01-04).
</objective>
