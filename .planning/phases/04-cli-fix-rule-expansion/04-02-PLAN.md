## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rule patterns (regex strings) | Regex strings defined in source are compiled at runtime by `new RegExp(pattern, 'g')` in applyRules -- no user input reaches the regex engine directly |
| Replacement strings | Replacement strings contain $1/$2 capture group references; no code execution or eval |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-03 | Denial of Service | applyRules regex compilation | low | accept | 8 new RegExp objects created once per applyRules call; patterns are anchored with specific prefixes (overriding, cast from, calling a, etc.) -- no catastrophic backtracking risk |
| T-04-04 | Information Disclosure | Rule replacement strings | low | accept | Replacement strings are static Chinese text with capture group references; no user data, file paths, or secrets embedded in patterns |
| T-04-05 | Tampering | Regex injection via pattern strings | low | accept | Patterns are hardcoded string literals in source code, not constructed from user input; `new RegExp()` is called only on developer-authored strings |
| T-04-SC | Tampering | npm install (dev dependencies) | high | mitigate | slopcheck audit on package install; blocking human checkpoint for any [ASSUMED]/[SUS] packages |
